final class Budget[F[_]]

A limit on what requests may cost together, in US dollars, for a session or any other span a host chooses: every client it limits spends from it, whatever its model or provider. A request is refused once as much as the limit has been spent, and is charged what its reply cost when the reply comes. Its cost is known only then, so requests already sent when the limit is reached are charged in full, and may take the spending past it, by as many requests as are in flight at once: a stream running then among them, which goes on to its end. A stream stopped before its end reports no usage, so is charged nothing, though the provider may charge for what it wrote. What is spent never resets, so a budget for each day, say, is a new budget each day.

final case class Chat(messages: List[Message] = ..., instructions: Option[String] = ...)

The full history of a conversation with a model, sent whole with every request. To continue a conversation, append the model's reply and the next user message, then send the chat again:

The full history of a conversation with a model, sent whole with every request. To continue a conversation, append the model's reply and the next user message, then send the chat again:

for
 first     &lt;- client.ask[String](chat)
 responses &lt;- first.responses
 next       = chat.modelSays(responses.last).userSays("Tell me more.")
 second    &lt;- client.ask[String](next)
yield second.value

Asked of a chat ending with the model's message, the model is told what to answer in a message of the user's after it, and so answers afresh rather than continuing its own reply. A chat with no messages, a message of breakpoints alone, or no message of the user's fails with ModelError.Unsendable before any request is made.

trait Content[A]

What may be said to the model: how a value is written as a part of a message, wherever a Chat or Message takes one. Values of different kinds mix freely there, each said as its own type's content:

What may be said to the model: how a value is written as a part of a message, wherever a Chat or Message takes one. Values of different kinds mix freely there, each said as its own type's content:

chat.userSays("Review this draft.", draft, MessagePart.CacheBreakpoint, "Be brief.")

A String is said as text, and a MessagePart as itself. A value of a type with a Schema is said as JSON as that writes it, so that it is written as the schema the model may be told describes it, and a value of another type with a circe Encoder as that writes it. A type given a content of its own is said as that says it, as a picture of one's own may be:

given Content[Scan] = scan => MessagePart.Media(MediaType.Png, scan.base64)

No other value can be said, and one holding an fs2 Stream has a schema but cannot be: saying it throws, as its stream would have to be run. Say a list of the stream's elements instead.

final class Schema[A]

How a type's values travel to and from the model as JSON: how a value is written, how one is read back, and the JSON Schema the model is told they conform to. ModelClient.ask asks for a type with one, and Content says one.

How a type's values travel to and from the model as JSON: how a value is written, how one is read back, and the JSON Schema the model is told they conform to. ModelClient.ask asks for a type with one, and Content says one.

Strings, numbers, Booleans, options, lists, vectors, sequences, sets, maps keyed by strings, tuples, eithers, unions and literal types have one, and so does every case class, sealed trait and enum whose fields have one, derived wherever it is needed, but for one with a circe Encoder of its own, which is said as that writes it:

case class Person(name: String, age: Int, nickname: Option[String] = None)

client.ask[Person](Chat.userSays("Who wrote Middlemarch?"))

derives Schema derives one once, beside its type, rather than wherever it is needed, even for a type with an Encoder of its own, and names any field whose type has none. Circe's Json has none, as it would tell the model nothing.

A case class, or a named tuple, is an object of its fields, of which one that is optional or has a default may be left out, and is read as None or its default. A sealed trait or enum whose cases have no fields is the name of one of them, as "Red"; any other is an object holding one case under its name, as {"Circle":{"radius":1.0}}, as an Either holds its value under Left or Right, and a union under the name of its alternative, as {"Int":1}, which a value's class must tell, but for a union of literal types alone, which is one of their values. A tuple is an array of its elements, and an fs2 Stream an array of its values, which ModelClient.ask delivers as the model writes them, but which cannot be said as JSON. A recursive type refers to itself through definitions in the schema, each type told apart by its full name and type arguments, so that Tree[Int] and Tree[String] are each defined.

The schema describes a derived type, each of its cases and each of its fields as its Scaladoc does: a type or case by its description, and a field by its class's @param tag, followed by its type's description. Code examples are left out, and links written as their labels. A comment is read only where its type is compiled alongside, as it always is for derives Schema, or anywhere under -Xread-docs, and never under -Xdrop-docs.

In JavaScript, a reply's numbers are read as doubles, so a Long, BigInt or BigDecimal beyond 2^53^ is read imprecisely.
