Forwarding

com.alecdorrington.iris.ModelClient.Forwarding
abstract class Forwarding[F[_]](val underlying: ModelClient[F]) extends ModelClient[F]

A client passing every request on to another, for a wrapper to override only what it changes. It passes ModelClient.warmCache on too, which the default would send through ModelClient.send instead. A wrapper seeing every request overrides all four: send and ModelClient.stream, which every attempt of an ask goes through, one or the other by the type asked for, and ModelClient.countTokens and ModelClient.warmCache, which go their own ways, each passing it on through super.

final def ask[A](chat: Chat, options: Options = ..., attempts: Int = ..., tools: List[RunnableTool[F]] = ...)(using evidence$1: Schema[A], Async[F]): F[ValidatedResponse[F, A]]

Asks the model for its next response to a chat, with a value of a type read from it and validated against the type's schema: the one way a caller has a response, as countTokens and warmCache have none to read, alike for every type.

Asks the model for its next response to a chat, with a value of a type read from it and validated against the type's schema: the one way a caller has a response, as countTokens and warmCache have none to read, alike for every type.

Every type is asked for alike, String as much as a case class of one's own: the model is told the type's JSON Schema, closing the chat's last user message, and its reply read as JSON conforming to it. A reply that cannot be read is followed by why, and the model asked again, until one can be or the attempts run out, but not where asking again could not help: a reply cut off at the token limit, which is never read, stopped for a reason of the provider's, such as a refusal, or saying nothing. A reply asking for a tool is given with no value. A chat in which the user says nothing fails with ModelError.Unsendable before any request.

case class Person(name: String, age: Int)

client.ask[Person](Chat.userSays("Invent a person.")).map(_.value)

The answer is given as soon as everything in its value but its streams is read. Each fs2.Stream within the type, other than within a list or map, which are read whole, then delivers each of its elements as soon as the model has written it whole, while the reply goes on being read to its end in a fiber of its own; ValidatedResponse.responses gives every response once the last ends. Only streams are ever partial: every other value is read whole first. A type holding no stream is asked with one request, through send, and given once its reply ends; any other, through stream, each attempt going through the one or the other, so a wrapper overriding both sees each.

case class Page(title: String, words: Stream[IO, Word])

client.ask[Page](chat).flatMap(answer =>
 answer.value.traverse_(_.words.evalMap(show).compile.drain),
)

The model is told the same JSON Schema whether its reply streams or not, a stream being an array, so its reply is no different; only its reading is. The model writes a value's fields in order, so a value holding a stream is given once each field it has begun is read or begun as a stream, each it has passed over is one that may be left out, and each it has yet to begin is a stream it must write, given to begin when it does: so a value's streams are delivered as they are written wherever every field after them is a stream, and any other is whole by the time the field after it begins. A field it writes after its value was given, or a stream it never begins, fails the reply. Every stream may be read as often as wanted, each time from its first element. A streamed reply's JSON is read from its start, or from within a code fence it opens with, and reading ends with it: what follows, which a reply read whole would be refused for, is not read; one that does not begin with its JSON is read only once whole. Once an answer is given, it is never asked for again: whatever fails afterwards fails each of its streams not yet ended, after the elements they have delivered, and ValidatedResponse.responses, with ModelError.UnreadableResponse where the reply cannot be read to its end, as one cut off at the token limit, stopped, or asking for a tool, as a whole reply would, and as the request fails where that fails partway, as one timing out. A streamed reply is read to its end even where nothing reads its streams, unless ValidatedResponse.cancel stops it, and its failure reaches only its streams and ValidatedResponse.responses. A value is given early only while one of its streams is seen open, so how a reply's parts arrive may decide whether it is.

Type parameters

A

The type of the answer, whose streams are of this client's effect.

Value parameters

attempts

The most replies to ask for before an answer is given, three unless given, which must be at least one, as the effect otherwise fails with an IllegalArgumentException; a reply asking for tools that are run does not count. Given through emit, the most times in a row an element may be emitted unreadable.

chat

The conversation so far, including any system message.

options

The per-request options, alike for every attempt; unset fields fall back to the configuration or the provider's defaults.

tools

The tools to offer the model and run wherever it asks for them, beside any ModelRequest.Options.tools offered for the host to run: a reply asking for these alone is followed by their outputs, and the model asked to go on, as often as it asks. Given tools, an answer that is itself a fs2.Stream is given element by element through a tool of its own, emit, so that the model may run the others between elements, and ends with the reply in which the model calls another, done. No tool may then be offered for the host to run, nor one named emit or done, as the effect otherwise fails with an IllegalArgumentException. A tool whose run fails fails the ask, or the stream and ValidatedResponse.responses where its answer was given, the model not told. Tools are run for as long as the model asks for them, each round a request whose cost is the host's to bound, as for any request's: unbounded, a model that never stops asking for them is asked again without end. Each request after a round closes with a MessagePart.CacheBreakpoint of its own, so that it reads the rounds before it from the cache, writing only its own; Anthropic marks it only where the chat's own breakpoints leave room. The first such request writes all after the chat's last breakpoint, the whole prompt where it has none, so end a fixed prefix with one to keep the writes to rounds.

Attributes

Returns

An effect producing the answer, as soon as it can be given. It fails with ModelError.UnreadableResponse where the last reply could not be read either.

final def metered(meter: (Usage, Option[Usd]) => F[Unit])(using Monad[F]): ModelClient[F]

Runs a function on what each request this client makes spent, as its reply comes: once for every attempt of an ask, on that attempt's reply before it is read, so an ask that fails after three attempts is metered three times, once for warmCache, and once for each stream, at its Delta.End. countTokens costs nothing, so is never metered, nor is a request that fails with no reply, nor a stream stopped before its end, which reports no usage. The meter runs before the reply is handed on, so a meter that fails fails the request, and the meters of requests sent at once may run at once.
