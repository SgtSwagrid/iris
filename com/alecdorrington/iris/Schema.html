Schema

com.alecdorrington.iris.Schema
See theSchema companion object
final class Schema[A]

How a type's values travel to and from the model as JSON: how a value is written, how one is read back, and the JSON Schema the model is told they conform to. LlmClient.ask asks for a type with one, and Content says one.

Strings, numbers, Booleans, options, lists, vectors, sequences, sets, maps keyed by strings, tuples, eithers, unions and literal types have one, and so does every case class, sealed trait and enum whose fields have one, derived wherever it is needed, but for one with a circe Encoder of its own, which is said as that writes it:

case class Person(name: String, age: Int, nickname: Option[String] = None)

client.ask[Person](Chat.of("Who wrote Middlemarch?"))

derives Schema derives one once, beside its type, rather than wherever it is needed, even for a type with an Encoder of its own, and names any field whose type has none. Circe's Json has none, as it would tell the model nothing.

A case class, or a named tuple, is an object of its fields, of which one that is optional or has a default may be left out, and is read as None or its default. A sealed trait or enum whose cases have no fields is the name of one of them, as "Red"; any other is an object holding one case under its name, as {"Circle":{"radius":1.0}}, as an Either holds its value under Left or Right, and a union under the name of its alternative, as {"Int":1}, which a value's class must tell, but for a union of literal types alone, which is one of their values. A tuple is an array of its elements. A recursive type refers to itself through definitions in the schema, each type told apart by its full name and type arguments, so that Tree[Int] and Tree[String] are each defined.

The schema describes a derived type, each of its cases and each of its fields as its Scaladoc does: a type or case by its description, and a field by its class's @param tag, followed by its type's description. Code examples are left out, and links written as their labels. A comment is read only where its type is compiled alongside, as it always is for derives Schema, or anywhere under -Xread-docs, and never under -Xdrop-docs.

In JavaScript, a reply's numbers are read as doubles, so a Long, BigInt or BigDecimal beyond 2^53^ is read imprecisely.

inline def emap[B](to: A => Either[String, B])(from: B => A): Schema[B]

Writes and reads another type as this one, with the same schema, refusing some values read, as for a number within bounds. The model is told why a value was refused, as for any other that could not be read. The other type's Scaladoc describes it, where it has one, and otherwise this type's.
